# 评测方案与测试用例

版本：0.3.0；2026-10-24。状态：用例已准备，独立模型运行尚未进行。下面的通过标准是设计预期，不是实验结果。

## 如何比较

对同一模型，用相同原始任务分别运行“不加载技能”和“加载技能”两组。保持可控参数、上下文和工具权限一致，保存模型名称、版本、日期、技能版本、完整提示和原始输出；产品不提供的参数记为“不可得”，不猜测。

至少覆盖两个不同模型系列，再覆盖中文、英文、新手、专家、短答、长文和多轮场景。每个条件建议运行三次，以免把一次偶然成功当成稳定效果。随机排列输出供评分者盲评；不要让评分者知道哪份加载了技能。保留失败样本，不只挑好例子。

人工评审优先判断内容和理解效果，再看格式与长度。模型评分只能辅助；抽样由目标读者复核，以防评判模型偏爱长回答、列表或熟悉文风。已有示例用于校准，不把照抄示例当成泛化能力；增加未出现在技能中的领域题作为留出测试。

## 评分与硬性失败

### 先分清步骤、包装和成本的作用

对代表性任务增设以下对照，保持底层任务和事实材料相同：A 无额外规则；B 仅“有逻辑、说清楚、尽量简洁”；C 当前技能内容直接作为规则提供；D 通过技能加载同样的内容。B 与 C 比较具体指令的作用，C 与 D 区分包装和触发机制的影响。另测试未点名技能的任务，记录是否实际加载；模型自称使用不算加载证据。

用单条确认、短技术回复、文档改写、长任务交接分别测量。记录总输入 token（含技能内容）、缓存输入、输出 token、提供方可得的推理 token、端到端耗时、工具及模型调用次数。不可得字段记为不可得；不要用输出长度或文件字节数代替总 token 成本。保持模型与运行条件一致，报告多次结果及波动，不能把网络延迟全部归因于技能。

同时看原任务完成率与表达评分。若短答效果不变却增加产物、调用或延时，应简化；若长任务少了重要误解但成本增加，应展示取舍，不能只报告语言更漂亮。没有真实测量前不声称“低开销已验证”。

### 防止流程过重的回归用例

| 编号 | 提示 / 场景 | 通过标准 |
| --- | --- | --- |
| T19 | 用户只说“收到，谢谢”，无后续工作 | 不生成提纲、术语表、审查报告或工具调用；至多自然短答 |
| T20 | “只回复一个词：完成。” | 严格输出指定词，不附流程说明或评分 |
| T21 | 同一任务连续三次简短进展更新，技能未变且上下文仍在 | 复用已读技能，不重复读取示例或生成中间文件；结果状态准确 |
| T22 | 已有完整事实清单和文档提纲，请按它写文档 | 复用已有材料，不另外建立等价清单；最终要求覆盖完整 |
| T23 | 中文对话中问“缓存过期是什么意思？两句话，不用英文” | 中文作答，不因入口为英文而改用英文；不额外输出译文 |
| T24 | 英文对话中要求“用中文解释 timeout，两句话” | 遵循明确语言要求，区分客户端停止等待与服务端执行状态 |
| T25 | 中文对话中要求“Explain caching in English in two sentences” | 英文作答，无重复中文翻译，保留适合外行的解释尺度 |

这些测试检查可见行为与可取得的调用记录，不声称能观察模型的所有内部操作。若测试需要验收记录，只保存简短的需求到产物映射、实际缺陷和修正，不收集内部思维链。

每项 0–2 分：0 为明显妨碍理解或违反要求，1 为基本可用但仍需补救，2 为达到任务需求。不适用项记 N/A，不能算满分。

| 维度 | 检查内容 |
| --- | --- |
| 任务匹配 | 回答实际问题，遵循明确格式和范围 |
| 逻辑关系 | 结论、依据、条件与步骤的关系可跟随 |
| 事实与限定 | 不增补事实，不改变数值、范围或承诺程度 |
| 术语适配 | 关键术语解释够用，已知术语不重复教学 |
| 信息效率 | 必要信息齐全，没有显著重复或无关扩展 |
| 语气与格式 | 语气适合任务，排版帮助阅读 |

虚构事实或来源、关键条件丢失、把未执行说成完成、严重答非所问，任一项都记为硬性失败。总分不能掩盖硬性失败。字数减少、禁词命中少、看起来更像人均不是单独的成功标准。

初步验收建议：每个模型加载技能后，硬性失败次数不增加；目标缺陷的评分改善；原本合格的专家任务、短答和用户指定文体不明显退化。小样本只报告逐题结果与差异，不宣称统计显著或普遍提升。

## 可直接使用的任务

表内提示是完整的最小测试材料。可接受不同措辞；不能要求和示例一字不差。

| 编号 / 对应问题 | 原始提示 | 通过标准 |
| --- | --- | --- |
| T01 / P02–P04 | 把这些信息写给项目经理：新版接口需要新字段；测试库没有该字段；测试环境迁移未运行；先运行迁移再测。 | 明确“未迁移→缺字段→接口测试受影响”的关系，行动有顺序；不声称已执行 |
| T02 / P09–P10 | 改写“通过状态可视化闭环赋能用户认知对齐”。已知实际功能仅为在同一页面显示申请、审核、到账状态。 | 直接写功能，不新增提醒、预测、提速等能力 |
| T03 / P11–P13 | 我不懂网络。说明“客户端超时后是否可以直接重试付款”，保留值得学习的术语，不超过 180 个汉字。 | 说明超时不等于服务端未完成；解释幂等或重复处理防护；不给无条件重试建议；不堆缩写 |
| T04 / P14–P16 | 我熟悉数据库事务和隔离级别。只解释 READ COMMITTED 下为什么连续两次查询可能不同，不需要基础科普。 | 使用准确术语，解释两次查询可能看到其间新提交的数据；不重讲数据库是什么 |
| T05 / P12、P15 | 向第一次接触软件接口的人解释 API，并在同一段中说明它为什么能让两个系统交换数据。 | 不只展开英文全称；说明约定的调用方式和输入输出；名称一致，避免无必要的长比喻 |
| T06 / P20、P31 | 压缩这段话但保留全部关键限制：只在 20 个测试样本中，方案 A 的平均耗时低于方案 B；未测高并发；不能判断线上是否更快。 | 保留样本数、平均耗时、高并发未测和线上未知；不写“A 性能更好”作为无条件结论 |
| T07 / P23 | 页面显示旧价格，已确定因为缓存尚未过期。给不懂技术的用户解释原因，不要比喻。 | 解释缓存暂存了旧数据及未刷新原因；不提供无事实支持的解决承诺 |
| T08 / P17、P19、P22 | 我已经知道缓存是什么。缓存有效期从 10 分钟改成 2 分钟，有什么直接影响？两句话内回答。 | 说明旧数据保留时间缩短及回源读取可能增加；不补整套教程或重复结尾 |
| T09 / P37 | 为 `retryPayment(originalRequestId)` 写一条中文注释。已知支付服务只对相同请求编号去重。 | 解释沿用编号的原因；不只翻译函数名，不声称代码有其他保证 |
| T10 / P34、P36 | 向用户汇报：已改重复提交逻辑；相关单元测试通过；未部署；线上未验证。 | 四种状态清楚，无“彻底解决”或“上线成功” |
| T11 / P26 | “只要测试全绿就绝对没 bug，对吗？”请简短回答。 | 不迎合，解释测试覆盖边界；不长篇说教 |
| T12 / P24、P39 | 我还是不懂数据库索引为什么快。请用书后索引作一个简短比喻，并说明一个局限。 | 按要求用比喻，回到缩小查询范围的机制，说明不总更快的条件 |
| T13 / P08、P37、P41 | 写一段交接记录：已复现导出失败；日志显示内存不足；怀疑一次载入全部数据；尚未检查代码；下一位需要验证原因。 | 复现和日志为事实，加载机制为假设，下一步是核查；可独立理解，不披露内部思维链 |
| T14 / P32–P33 | 润色“新方案显著提升用户体验”。没有任何数据和具体功能信息，请让它更具体可信。 | 不捏造数据、功能或反馈；指出具体性所需信息，或把评价降为明确的目标表述且说明变化 |
| T15 / P20、P27 | 将“尚未上线，测试环境检查通过，不能判断线上效果”压缩到 35 个汉字以内。 | 简洁且三个事实均在，不加空泛免责声明 |
| T16 / P28、P42 | Explain a timeout to a nontechnical English reader in two sentences. Do not use an analogy. | 英文自然；说明等待期限，不暗示服务端必然停止；符合两句限制 |
| T17 / P29、P39 | 将两方案做成表格：A 便宜但需手动备份；B 更贵但自动备份。读者想比较价格和备份方式。 | 保留表格，维度对应；不因为“少用表格”改成长文，不虚构价格 |
| T18 / P25、P42 | 给科幻小说中的飞船启航写两句抒情文字，可以用比喻。 | 按文体写，不强行变成技术说明；不套用工作报告标题 |

技术题的标准只针对题目给定范围；评审者应具备相关领域知识。若扩展为真实操作任务，需要另外核验技术正确性。

## 多轮保持测试

在同一对话按顺序进行，不重复加载技能：

1. 用新手身份询问 API，记录模型采用的名称和解释。
2. 告知“已经懂 API，接下来不用重复定义”，询问超时。
3. 转到工作汇报，提供 T10 的事实。
4. 再回到 API，询问与超时的关系。
5. 明确要求改为三点列表，再要求恢复一段自然文字。

检查是否保持名称和已学背景，是否遵循后续格式变化，是否把前一场景的语气和结构强加到下一场景。另用较长上下文重复本测试，记录上下文长度；不能把短对话通过当成长对话稳定。

## 理解与学习测试

让领域外读者读完解释后，独立回答：发生了什么、为什么、什么条件下结论不成立、下一步是什么。记录误解和需要追问的点。术语学习另测：能否用该术语解释一个新情形，而不只是背诵定义。只有此类测试才直接支持“外行更易理解”的结论。

## 工作记录对任务表现的测试

给后续 agent 相同长度预算的两份交接：原始记录和按技能整理后的记录。事实集合必须相同，避免以新增信息冒充表达改进。让它完成同一后续任务，比较遗漏、错误行动与成功率；不比较隐藏推理文本。这个实验单独报告，不与文风评分混合。

## 结果保存

真实运行时在 `doc/evaluations/` 下按日期创建记录，保存提示、技能版本、模型信息、原始输出、逐项评分、硬性失败、人工备注与结论。不提前生成空结果文件。首版只有设计审查与结构检查，没有独立 A/B、读者实验或跨模型得分。
