中文备选：

## 文件职责

| 文件 | 角色 |
| --- | --- |
| `README.md` / `README.en.md` | 中文首页与英文首页，互相链接 |
| `doc/installation.md` / `doc/installation.en.md` | 两种语言的完整安装与启用说明 |
| `skills/clear-communication/SKILL.md` | 唯一运行指令，英文，明确遵循用户输出语言 |
| `doc/skill.zh-CN.md` | 供人阅读和维护的中文对照，不参与技能发现或默认加载 |
| `references/examples.md` / `references/examples.en.md`（技能包内） | 对应编号的中英文示例，根据输出语言按需选择 |
| 其余 `doc` 文档 | 目前以中文记录调研、设计与测试，不宣称全部已翻译 |

采用单一技能名和入口，避免两个技能争抢触发，以及每次加载两套同义指令。英文入口是为了跨语言协作方便，不是基于已验证的性能优势。中文对照与开发材料留在包外，避免增加运行依赖。

## 更新约定

修改行为规则时，同步运行入口和中文对照；修改安装流程或目录时，同步两份安装说明。新增示例时保留相同编号、事实前提与关键限制，用目标语言自然表达，不机械逐字翻译。

README 两个版本可以使用自然的不同句子，但功能范围、安装范围、版本、限制与验证状态必须一致。开发研究不强制每次双份记录，以免翻译工作挤占技能本身的迭代；影响使用的结论应同步到双语用户文档。

技能不默认输出两种语言。明确指定语言优先，其次跟随对话；代码、命令和标准名称保留精确形式，译名或英文括注只在帮助理解时使用。

## 新增评测要求

在相同事实和任务下分别测试中文、英文输出，再测试中文对话中明确要求英文、英文对话中明确要求中文。检查语言切换、术语解释尺度、事实保持，以及是否无故输出双语。核对按需示例读取记录，避免同时加载两份。

如果要判断英文入口是否更好，应比较内容等价的中文和英文指令，并记录理解效果及实际 token、耗时；文件字节数不能替代这些测量。目前尚未进行该实验。
