# Agent / AI 写作问题清单

版本：0.4.0；更新：2026-10-25。

这份清单记录技能需要处理的可观察问题，不用于判断文字是否由 AI 撰写。问题在人类写作中也可能出现；不同模型、任务与读者的严重程度不同。来源类型与编号见 [调研记录](research.md)：U 为用户要求，R 为研究，G 为指南，C 为社区或评论，D 为本项目设计推论。

严重程度按影响判断：**高**表示可能导致误解、错误决定或无法完成任务；**中**表示增加阅读成本或削弱信任；具体情境可以调整。以下示例为项目自拟，修正方向须以真实上下文为准。

## 1. 回答与逻辑

| 编号 | 问题及可见表现 | 后果与修正方向 | 优先级 / 依据 |
| --- | --- | --- | --- |
| P01 | 不回答当前问题，先铺行业背景或泛谈重要性 | 读者找不到答案；先识别问题和必要结论 | 高；U、G1 |
| P02 | 关键前提缺失，从现象直接跳到结论 | 读者无法判断结论为什么成立；补足必要关系和条件 | 高；U、D |
| P03 | 想到哪写到哪，原因、行动、背景交错 | 读者自行重排内容；按理解依赖组织，而非按工作发生顺序罗列 | 高；U、G3 |
| P04 | 用“因此”“首先其次”制造表面逻辑 | 连接词掩盖无关或未经支持的推断；核对实际关系 | 高；U、C5 |
| P05 | 各段局部通顺，全文反复换话题或重复同一观点 | 文章没有推进；明确每段对主线的作用 | 中；U、C5、D |
| P06 | 列出大量选项却不给比较依据或建议条件 | 看似全面，读者仍无法决定；说明差异及适用条件 | 高；D |
| P07 | 指代不明、主语丢失，如“这样就能解决它” | 不知道谁解决什么；必要时重复准确对象名 | 高；U、D |
| P08 | 正文、摘要、结论相互矛盾，混淆前后版本 | 无法知道哪句有效；检查事实、名称、状态和范围的一致性 | 高；D |

## 2. 术语与知识适配

| 编号 | 问题及可见表现 | 后果与修正方向 | 优先级 / 依据 |
| --- | --- | --- | --- |
| P09 | 自造黑话，如“认知协同输出底座” | 没有稳定含义，无法检索或理解；说明具体对象、动作与关系 | 高；U |
| P10 | 用“赋能、闭环、抓手”等抽象词代替具体内容 | 隐去主体、行为和结果；在真实上下文中还原含义，不能换一组黑话 | 高；U、D |
| P11 | 连续抛出多个陌生术语或缩写 | 阅读依赖超出读者知识；按理解顺序逐步介绍 | 高；U、G1、G2 |
| P12 | 解释只展开英文全称，或用更难的词解释难词 | 看似定义过，读者依旧不懂；说明术语在当前任务中的含义或作用 | 高；U、G2、D |
| P13 | 面向外行时删掉全部术语 | 白话冗长且丢失概念精度，不利于学习；保留值得学习的标准名称 | 中；U、G2 |
| P14 | 每次重复定义已解释的术语 | 打断主线、显得居高临下；沿用已有共同知识 | 中；U、D |
| P15 | 同一概念频繁换名字，不同概念又合用一个词 | 读者误判差异或等价关系；保持术语一致，必要时说明区别 | 高；G1 |
| P16 | 知识层次忽高忽低，或把“不懂领域”当成“理解力差” | 一会儿幼稚比喻，一会儿密集专业词；尊重读者，按上下文补背景 | 中；U、C1、D |

## 3. 篇幅与信息量

| 编号 | 问题及可见表现 | 后果与修正方向 | 优先级 / 依据 |
| --- | --- | --- | --- |
| P17 | 开头预告、正文解释、结尾再完整复述 | 信息重复，阅读成本升高；摘要只有在导航或复用有价值时保留 | 中；C3、C5 |
| P18 | “非常重要、影响深远”等评价没有具体所指 | 文字很多，信息很少；给事实与影响，无依据就删评价 | 中；C5、D |
| P19 | 用户问局部问题，回答扩大成整套教程 | 当前答案被淹没；控制范围，把必要背景与扩展学习区分 | 中；U、C3 |
| P20 | 为了简短删掉条件、单位、例外或依据 | 简短但错误或不可用；先保完整含义，再压缩 | 高；U、D |
| P21 | 省略成名词串或口号，如“缓存、并发、提速” | 读者必须补关系；用完整句子交代因果或步骤 | 高；U、D |
| P22 | 结尾惯性附加邀请、承诺或无关下一步 | 增加交互负担；只有实际需要继续协作时才提出 | 中；D |

## 4. 修辞、语气与版式

| 编号 | 问题及可见表现 | 后果与修正方向 | 优先级 / 依据 |
| --- | --- | --- | --- |
| P23 | 简单机制也先讲长比喻，甚至连续换比喻 | 只理解故事，没理解内容；优先直接解释和领域内小例子 | 中；U、C1 |
| P24 | 比喻映射不准确，用比喻替代证据 | 形成错误模型；回到真实机制，说明影响判断的边界 | 高；U、D |
| P25 | 反复“不是 X 而是 Y”、自问自答、排比升华 | 无必要的对立和悬念打断解释；直接陈述真实判断 | 中；C4、C5 |
| P26 | 习惯性赞美、夸张认同、假装熟悉用户 | 降低可信度，可能强化错误前提；有依据地赞同或纠正 | 高；R3、C2 |
| P27 | 过度保守，每句堆叠“可能、或许、仅供参考” | 无法判断哪里真的不确定；标出具体未知及其影响 | 中；D |
| P28 | 术语翻译腔、公文腔、英文夹杂没有实际作用 | 阅读费力；选择自然中文，保留必须精确的原名与标识符 | 中；U、D |
| P29 | 一句话一行，标题、加粗、表情、列表层层堆叠 | 结构割裂，视觉重点过多；按信息关系选择格式 | 中；R2、C2、C4 |
| P30 | 任何问题固定分三点、所有段落等长 | 形式反过来决定内容；允许自然篇幅和不同文体 | 中；R1、C5、D |

## 5. 事实、证据与任务交付

| 编号 | 问题及可见表现 | 后果与修正方向 | 优先级 / 依据 |
| --- | --- | --- | --- |
| P31 | 用肯定语气包装猜测，泛称“研究表明”而无依据 | 文风掩盖证据不足；区分事实、推断、建议和未知 | 高；R3、D |
| P32 | 为了具体生动而虚构数字、来源、经历或例子 | 产生错误事实；教学情境明确标为假设，事实细节须有来源 | 高；D |
| P33 | 改写后承诺变强、条件消失、作者立场改变 | 文字顺了，意思却变了；逐项核对事实和限定 | 高；U、D |
| P34 | 把“准备做、已修改、测试通过、已部署”混写为“解决” | 用户误判工作状态；报告实际完成与验证范围 | 高；D |
| P35 | 泛泛建议不可执行，缺少必要对象、步骤或前提 | 看懂意思仍不能做；按任务补齐执行所需信息 | 高；G1、D |
| P36 | 工作报告照搬日志、路径和试错过程 | 用户要自己提取结果；保留关键证据、结果与未解问题 | 中；D |
| P37 | 注释复述代码，文档依赖“如上”或聊天记忆 | 不解释约束，交接后失效；写清意图与独立使用所需背景 | 中；D |

## 6. 持续性与规则误用

| 编号 | 问题及可见表现 | 后果与修正方向 | 优先级 / 依据 |
| --- | --- | --- | --- |
| P38 | 换模型或长对话后，名称、语气与解释尺度漂移 | 体验不稳定；统一质量原则，评测多轮保持与跨模型差异 | 中；U、R1、C2 |
| P39 | 把风格建议做成禁词表，见破折号或列表就删除 | 误伤有效表达；按功能和上下文判断 | 中；D |
| P40 | 为了“像人”故意加错别字、虚构个人经历或口癖 | 降低准确性并制造虚假身份感；以理解效果而非伪装为目标 | 高；D |
| P41 | 把“解释理由”变成冗长的内部思考展示 | 淹没答案，混淆草稿与证据；提供可核查的理由摘要 | 中；U、D |
| P42 | 为了统一风格抹去文体和读者差异 | 注释像教程，回复像论文；统一原则，按任务选择表达 | 中；U、R1、D |
| P43 | 阅读差文档后沿用其空泛句式，把已有表达当成默认风格 | 新内容继续制造理解负担；提取事实与名称，重新清楚表述 | 中；U、D；研究边界见 [已有材料设计](existing-material.md) |
| P44 | 为了改善文风擅自重写读过的文件或无关章节 | 扩大 diff、增加审查和合并负担；只改善任务正在修改的完整语义片段 | 高；U、D |
| P45 | 为去黑话局部重命名已有概念，或猜测含混旧词的意思 | 搜索、界面和引用失配，可能改变行为含义；保留可定位名称并解释，歧义影响任务时核实 | 高；U、D |

## 使用方式

记录失败时指出具体句子、读者和任务，再选问题编号。同一段可能同时命中多个问题，但不要按“命中数量”机械评分。优先修复事实和理解障碍，然后修复冗余与风格。

清单中的事实、推理、执行问题只能由写作技能部分缓解。它能要求清楚表达证据和限制，不能替代领域知识、工具验证或正确的实际执行。
