# 0.3.0 审查与 0.3.1 修正

日期：2026-10-25。方法：检查技能入口、中文对照、示例和评测设计，并对照边界任务审阅规则含义。此次是静态设计审查，没有独立模型运行，也没有测量 token 或延时。

## 发现与处理

| 问题 | 原文依据与影响 | 处理 |
| --- | --- | --- |
| 工作优先被写成时间顺序 | `Complete the task first` 可能被理解为完成后才沟通，与进度更新用途冲突 | 改为任务优先，并保留有用或必要的进度更新 |
| 复杂流程触发过宽 | `options need comparison` 涵盖简单两项比较，与低开销目标冲突 | 限定为涉及相互牵连的取舍，简单比较走默认路径 |
| 简洁目标没有进入默认检查 | 顶部要求简洁，默认四项检查却没有删除冗余的具体动作 | 合并到原有“回应问题”检查，不新增一步 |
| 固定格式边界不够直接 | 正文保留 fixed formats，但没有明确禁止追加检查说明 | 在语言和输出约定处写明精确输出及机器可读格式不得追加说明 |
| 少用工具可能被泛化 | `Do not add tool calls ... by default` 未明确只针对表达润色 | 限定为不为润色额外调用，不妨碍实际执行和事实核验 |
| 信息不足时只有不编造，缺少下一步 | 有 acknowledge missing facts，但未说明何时问、何时用假设 | 只对会实质影响答案或行动的缺失信息针对性处理，不重问已知偏好 |
| 回归题与示例高度重合 | T01–T18 多个问题沿用缓存、付款、测试等教学情境 | 标明其证明范围，增加会议、印刷、配送和格式边界等 T26–T31；不收入运行示例 |

## 暂不增加的内容

不增加常驻的长检查表、第二个评审模型或自动文风评分器。现有四项默认检查足够承载本次修正。也不因静态审查发现歧义就宣称已经观察到模型失败；表中的影响是风险推断。

## 仍需验证

最重要的缺口是独立行为与成本数据，而非规则数量。下一轮宜先挑选短答、术语解释、条件保留、长文各一类，加上新的领域测试，比较笼统规则、具体指令和技能加载三种条件。需要保存原始输出与实际可取得的成本信息。

当前示例仍偏软件领域；本次先在包外测试迁移效果，只有真实失败表明缺少某类指导时，再增加运行示例。这样避免为了看起来全面而持续扩大技能包。

本次修改仅在本地，未提交或推送。结构检查结果记录在版本记录；这些检查不能证明模型会遵循规则。
