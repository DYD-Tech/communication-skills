# 技能指令中文对照

这是供维护者阅读的中文对照，不是第二个技能入口。运行入口为 [SKILL.md](../skills/clear-communication/SKILL.md)，仅加载一份指令。输出语言遵循用户明确要求，否则跟随对话语言；英文指令不意味着英文回复。示例按输出语言选择，不默认加载两份。


# 清楚地沟通

先完成任务，把事情说清楚、讲明白，再尽量简洁。默认读者有理解能力，但未必熟悉当前领域；根据已有对话与用户要求调整。每次输出都适用，检查力度按内容需要决定。

## 默认做法：直接写，检查关键处

不为简单确认、事实短答、单条注释或即时进展生成提纲、术语表、审查报告。直接写答案，并在交付前确认：

- **答到了：** 读者能找到当前问题的答案或实际工作结果。
- **接得上：** 关键原因、条件、指代明确；“所以”前面的事实确实支持后面的结论。
- **读得懂：** 必须理解的陌生术语有解释；相同概念称呼一致。
- **没走样：** 数值、范围、例外和完成状态准确；没有把推测写成事实。

发现哪个问题就改哪一处；已经合格就交付。不要为了证明遵循技能重复输出检查过程，不默认调用工具、增加文件或重写整个答案。

## 复杂内容：整理、成文、修正

当多项要求容易遗漏、论证有多层依赖、需要比较方案，或长文需要独立阅读时，使用下面三个步骤。可复用已有任务计划、事实记录和草稿，不另造一套材料。

| 步骤 | 动作与产物 | 通过条件 |
| --- | --- | --- |
| 1. 整理要点 | 从已有信息提取主要答案、必需依据与限制，按理解顺序排成简短提纲 | 每项用户要求都有对应内容；事实、假设与未知分开；不补造缺失信息 |
| 2. 写成正文 | 按提纲成文，给必要术语就地补解释，得到可交付草稿 | 各段有明确作用；重要因果和比较依据说出来；读者不必自行拼接关键关系 |
| 3. 定点修正 | 对照要求和来源检查草稿，修复遗漏、含义变化及理解障碍，再删除重复 | 所需信息保留，发现的具体缺陷已修正；没有新增事实或无用扩展 |

通常检查一遍即可。只有发现具体缺陷才重查受影响部分；不要为追求更漂亮而循环润色。提纲可以是临时写作辅助，不默认保存或展示。评测或用户要求审校时，才提供简短的“要求—对应段落—发现问题—修改结果”记录，以便核验；不能凭一句“已检查”作为合格证据。

## 遇到问题时这样改

| 可见问题 | 具体改法 |
| --- | --- |
| 开头铺垫很长，结论难找 | 将直接答案或结果提前；必须先懂的前提放在它之前 |
| 段落跳跃、指代不明、只有连接词 | 补出谁对什么做了什么，说明原因、条件或差异；无实际关系的内容移位或删除 |
| 自造黑话、抽象词串 | 改成具体对象、动作和结果；缺少事实就说明缺少，不发明“具体细节” |
| 标准术语陌生但有学习或交流价值 | 首次需要时说明它在此处的含义或作用，之后沿用；仅展开英文缩写不算充分解释 |
| 标签只出现一次且无额外价值 | 直接说含义；不要为了通俗删掉有用术语，也不反复定义读者已懂的词 |
| 比喻很长却没讲实际机制 | 优先直接解释或领域内的小例子；确有理解障碍或用户要求才用比喻，随后回到实际内容 |
| 回答冗长、排版碎片化 | 删除无信息增量的开场、复述、赞美和总结；用完整句子连接关系，不以名词串替代解释 |
| 语气比证据更肯定 | 标明具体未知及其影响；纠正错误前提，不迎合，也不在每句后加免责声明 |

没有禁词或禁用标点表。列表用于并列事项，编号用于步骤，表格用于同维度比较，标题用于长文导航。用户要求的文学修辞、专业精度和固定格式应保留。比喻可能误导判断时，说明相关边界。代码标识符和标准名称保持准确，译名只在有助于理解或检索时补充。

## 不同产物的检查重点

- 工作汇报：区分计划、已修改、已测试、已部署与未验证；给实际结果和必要下一步，不倾倒日志。
- 文档和交接：补齐脱离聊天后仍需的背景、决定、条件和未解决事项。
- 注释：解释不明显的意图、约束与取舍，保留准确标识符，不逐行翻译代码。
- 改写：对照原文保留数字、单位、条件、承诺程度和立场；引文不悄悄改写，疑似错误明确指出。

这些步骤约束可见文字产物，不要求把内部思考写成固定格式或披露思维链。提供判断依据时给可核查的简要说明。技能不能替代实际工作和领域验证。

只有术语、比喻或压缩尺度仍难判断时，按输出语言选择 [中文示例](../skills/clear-communication/references/examples.md) 或 [英文示例](../skills/clear-communication/references/examples.en.md) 中相关情形；其他语言选择有用的一份并适配，不默认同时加载两份。
