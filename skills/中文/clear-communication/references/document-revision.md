# 成批改写已有文档

用户明确要求全面改写、统一术语或整理一批文档时，采用以下步骤。

## 1. 确认范围与含义

从任务中确定读者、目标和要改的文件。范围已经明确就开始，只追问会实质影响改写的问题。改写措辞时保留原有行为、需求、公开名称和历史记录。

阅读相关材料，确认必须保留的事实、条件、决定和例外。多个文件用了同一个生僻词时，先查项目定义、实现或已有决定，弄清它指什么，再决定是否换成通用说法。

在已有任务记录中简要列出改写范围。有歧义或需要跨文件统一的术语才单独记录，待确认的事实也应标明。

## 2. 按主题或依赖关系分批改写

每批改完后，相关文件应能一起阅读和检查。继续完成已获授权的各批内容。保留标识符和已有名称。用户要求更名时，同时更新相关引用，在读者需要按旧名称检索时保留别名或解释。

尽量让措辞修改和行为变更在差异中容易区分。保留可执行代码、指令、要求精确匹配的示例以及历史引文。生成的文档应在授权范围内改其源文件。遇到会改变原意的疑点，保留原文并指出具体疑问。

## 3. 核对含义与引用

逐批对照原材料，检查事实、数字、条件、例外、承诺和术语，并核对受影响的链接与锚点。文档或注释会被工具读取时，运行项目已有的相关检查。

有需要时先用少量样例校准语气，再把已明确的风格应用到其余部分。交付改完的文件，简要说明重要的术语或结构变化、实际覆盖范围及仍需用户决定的问题。
